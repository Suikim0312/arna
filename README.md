# Arna — деньги, которые знают, на что они

**Arna** — целевой кошелёк на Solana. Владелец кладёт деньги и задаёт правила: конверты с лимитами («Еда — 30 000 ₸ в неделю») и список разрешённых получателей. Распорядитель тратит сам, но только по этим правилам. Чужой адрес, превышение лимита или трата на паузе отклоняются программой в блокчейне, а каждая успешная трата сохраняется как публичный чек.

Итоговый проект курса Solana Builders (AlmaU), недели 14–15: свой MVP на Solana вместо Liquidity Vault.

> Название от казахского «арна» — «предназначение», «посвящение» (ср. «арналған» — «предназначенный для»).

---

## Проблема

Деньги «на что-то» сегодня держатся на доверии:

- родители переводят студенту на еду, а уходят они на что угодно;
- компания выдаёт бюджет на обеды или обучение и потом собирает чеки вручную;
- благотворительный фонд публикует отчёты, которые невозможно проверить.

Банковские карты с ограничениями есть, но правила задаёт банк, а не вы, и отчёт закрыт.

## Решение

| Кто | Что делает |
|---|---|
| **Владелец** (донор) | создаёт кошелёк, пополняет, добавляет конверты и получателей, ставит на паузу, меняет распорядителя, забирает остаток |
| **Распорядитель** | платит разрешённым получателям в пределах лимитов, обязательно указывает назначение |
| **Спонсор** | любой может пополнить кошелёк, правила остаются прежними |
| **Наблюдатель** | открывает ссылку и видит баланс, конверты и все чеки без подключения кошелька |

Почему блокчейн, а не обычная база данных: правила проверяет программа, а не сервер, который можно «подкрутить». Деньги лежат в хранилище, которым владеет PDA программы, поэтому ни распорядитель, ни разработчик не могут вывести их в обход правил. Отчёт нельзя подделать: он читается напрямую из блокчейна.

### Аккаунты (PDA)

| Аккаунт | Сиды | Что хранит |
|---|---|---|
| `PurposeWallet` | `["wallet", owner, id]` | владелец, распорядитель, токен, хранилище, суммы, пауза |
| хранилище | ATA(mint, wallet PDA) | сами токены; подписывает только PDA |
| `Category` | `["category", wallet, index]` | название, лимит, период (0 = без сброса), потрачено |
| `Merchant` | `["merchant", wallet, recipient]` | получатель, его конверт, активен ли, сколько получил |
| `SpendRecord` | `["spend", wallet, n]` | чек: кому, сколько, из какого конверта, назначение, время |

### Инструкции

`create_wallet`, `add_category`, `update_category`, `add_merchant`, `set_merchant_active`, `set_paused`, `set_spender`, `deposit`, `spend`, `refund`.

### Как `spend` защищает деньги

1. `has_one = spender`: подписать может только распорядитель.
2. Получатель ищется по PDA `["merchant", wallet, recipient]`. Если его нет в списке, аккаунта не существует и транзакция падает.
3. Конверт берётся из сидов `["category", wallet, merchant.category]`, поэтому подменить конверт нельзя (`ConstraintSeeds`).
4. Проверяются пауза, активность получателя, назначение, остаток в хранилище и лимит с учётом периода (неделя, месяц).
5. Только после этого `transfer_checked` через CPI в Token Program, подписанный PDA кошелька (`invoke_signed`).
6. Создаётся `SpendRecord`, обновляются счётчики, эмитится событие `Spent`.

Подробнее: [docs/architecture.md](docs/architecture.md).

## Запуск

Нужны Solana CLI 3.x, Anchor 1.1+, Node 20+.

```bash
# 1. Валидатор (отдельная вкладка)
solana-test-validator --reset

# 2. Сборка, деплой и тесты
solana config set --url localhost
solana airdrop 20
npm install
anchor build
# если репозиторий склонирован без target/deploy/arna-keypair.json:
#   anchor keys sync && anchor build && npm run sync-idl
anchor test --validator legacy --skip-local-validator   # 19 тестов
cargo test -p arna --lib                                  # 3 unit-теста

# 3. Консольный сценарий (пишет logs/demo.log)
npm run demo

# 4. Веб-приложение
cd app && npm install && npm run dev                      # http://localhost:5173
```

В веб-приложении откройте **Демо** → «Подготовить демо». Приложение само создаст роли «Мама», «Дана» и трёх получателей, выпустит тестовый тенге и настроит кошелёк. Дальше переключайтесь между ролями в тёмной полосе сверху.

Phantom и Solflare тоже работают: переключите кошелёк в тестовую сеть и выберите её в приложении.

### Devnet

```bash
solana config set --url devnet
anchor deploy --provider.cluster devnet
```

В приложении выберите Devnet в шапке. Program ID тот же: `BNmuXFFwkmzKLkxb96QvfSr642gVrMXWDTprTVDg2EhJ`.

### Если что-то не так

- `surfpool: No such file`: в Anchor 1.x по умолчанию другой валидатор, добавьте `--validator legacy`.
- `ExtendProgram was superseded` при повторном деплое: перезапустите валидатор с `--reset` или выполните `solana program extend <PROGRAM_ID> 2000`.
- В приложении «Кошелёк не найден»: проверьте сеть в шапке.

## Ограничения и что дальше

- Один токен на кошелёк. Дальше: несколько токенов и USDC.
- Получатели добавляются по адресу. Дальше: QR-код магазина и каталог проверенных получателей.
- Лимит считается по периодам. Дальше: лимит на одну покупку, запрет по времени суток.
- Несколько распорядителей и мультиподпись владельца (семья, совет фонда).
- Уведомления владельцу о каждой трате (события `Spent` уже эмитятся).

## Безопасность

- Все суммы с `checked_add`, переполнение даёт ошибку, а не обнуление.
- Хранилище принадлежит PDA; подпись только через `invoke_signed` с сидами кошелька.
- `has_one` проверяет владельца, распорядителя, токен и хранилище в каждой инструкции.
- `transfer_checked` сверяет decimals токена.
- Длины строк ограничены (48 байт названия, 96 байт назначения), размер аккаунтов фиксирован через `InitSpace`.
- Крупные аккаунты обёрнуты в `Box`, чтобы не выйти за 4 КБ стека BPF.
- Демо-ключи хранятся только в браузере и предназначены для тестовой сети.
